MindCycle / Arquitetura

Arquitetura

Como o MindCycle é construído: as tecnologias, como os sistemas conversam e por que escolhemos cada uma.

Visão geral

O MindCycle é um aplicativo Android que conversa com uma API. Só a API acessa o banco de dados, e é ela que decide, a cada requisição, quem é a usuária e o que ela pode ver.

Como os sistemas conversam

  1. Cadastro e entrada. O app envia e-mail e senha para /auth/cadastro ou /auth/entrada. A API guarda só o hash da senha (scrypt) e devolve um access token JWT, válido por 15 minutos, e um refresh token.
  2. Cada requisição. O app manda o access token no cabeçalho Authorization: Bearer. Um guard global da API valida o token e carrega a usuária. Toda rota exige autenticação, menos as marcadas como públicas, como a leitura dos termos de uso.
  3. Renovação. Quando o access token vence, a API responde 401 e o app troca o refresh token por um par novo em /auth/renovacao, sem a usuária perceber. Cada refresh token vale uma vez. Se um token já usado volta, a API trata como roubo e encerra a sessão inteira.
  4. Termos antes dos dados. As rotas que gravam ciclo, sintomas ou disposição passam pelo ConsentGuard: sem o aceite da versão vigente dos termos, a API recusa a gravação (RNF02).
  5. Erros. A API responde só com um código, como CREDENCIAIS_INVALIDAS. O app escolhe o texto exibido, revisado para não ter tom de cobrança (DoD, critério 5).

Decisões

Monorepo

App, API e pacote compartilhado no mesmo repositório, com npm workspaces. Um PR entrega a fatia vertical inteira de uma história, como o DoD pede.

Monólito modular

Uma única API, dividida em um módulo por domínio. Para uma equipe pequena e um MVP, microsserviços só trariam custo de operação.

Regras sem banco

A ordem das tarefas (HU13) e o reajuste (HU15) serão funções puras, testadas regra a regra sem depender do banco nem da tela.

Conta e PIN

A conta usa e-mail e senha. O PIN de pétalas (HU11) trava a sessão ao reabrir o app: 4 toques em 6 pétalas dão 1.296 combinações, pouco para ser a única credencial.

Fase do ciclo

O cálculo da fase (HU05) fica atrás de uma interface. Até a cliente validar o modelo, a resposta é "fase não estimada", com o motivo.

Sem serviços terceiros

Nada de backend como serviço: os dados de saúde ficam num banco sob controle do projeto, coerente com a LGPD e com o perfil de software livre do cliente.

Privacidade na arquitetura

RequisitoComo a arquitetura atende
RNF02 · LGPDO ConsentGuard bloqueia qualquer gravação de dado de saúde antes do aceite dos termos vigentes. Mudar o texto dos termos cria uma nova versão, que pede um novo aceite.
RNF03 · acesso exclusivoA identidade da usuária vem sempre do token, nunca de um id enviado pelo app. Cada módulo terá um teste que tenta ler dados com a sessão de outra conta e espera acesso negado.
HU36 · excluir contaOs dados da usuária ficam ligados à conta com exclusão em cascata: apagar a conta apaga tudo o que ela registrou e encerra as sessões abertas.

Situação

O esqueleto está pronto: estrutura do repositório, CI, Docker, criação de conta (HU25), aceite dos termos (HU12) e as telas de entrar, cadastro, termos e "Hoje", ligadas à API. Os próximos módulos entram na ordem do MVP: PIN, recuperação e exclusão de conta; ciclo e check-in; tarefas; planejamento do dia; conteúdos e acolhimento.

O texto dos termos de uso é um rascunho da equipe e precisa da revisão da cliente. O acompanhamento está na issue #55.
